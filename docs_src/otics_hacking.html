OT / ICS Hacking: Protocols & Tools

Cyber Club Quick Reference · v1.0

The hands-on companion to OT 101. That one explains why OT inverts your priorities — Safety, Reliability, Performance ahead of Confidentiality. This one is the practice: the protocol primitives that actually do things, the tooling, and the labs where you can run all of it without going near a plant. The discipline that separates OT work from IT work is simple to state and hard to hold to: in OT, reconnaissance is the dangerous part.

Passive first, always. An IT engagement starts with a scan. An OT engagement starts with a span port and a packet capture — because a single malformed probe has faulted PLCs and stopped production lines. Active testing happens on an offline twin, or during an agreed outage.

Methodology

Order matters
  1. Paper first. Network diagrams, asset inventory, firewall rules. Half the findings are visible before you plug anything in.
  2. Passive capture. SPAN/TAP. Identify protocols, masters, slaves and polling rhythms. Build the asset list from traffic.
  3. Baseline normal. You cannot spot an anomalous write if you never learned what a normal poll loop looks like.
  4. Targeted active work — only with written approval, on an offline twin or an agreed window, with operations in the room.
  5. Report in SRP terms. "This host can write coils" lands; "unauthenticated protocol" does not.

Rules of engagement

Non-negotiable
  • Written authorization naming the specific systems. No exceptions, ever.
  • Operations has a veto and a kill switch at all times. They own the process.
  • No active scanning on live control networks. Nmap's default scan has crashed controllers.
  • Never write to a live device — no coil writes, no logic downloads, no CPU stops.
  • Avoid broadcast and discovery storms; some fieldbuses collapse under them.
  • If something looks wrong, stop and say so immediately. A concealed mistake in OT becomes a safety event.

Modbus function codes — the practical subset

CodeFunctionReads / writesNote
0x01Read CoilsBoolean outputsRecon: current state of every digital output
0x02Read Discrete InputsBoolean inputsSensor states
0x03Read Holding Registers16-bit values The workhorse — most poll loops are this
0x04Read Input Registers16-bit, read-only Measured values
0x05Write Single CoilOne boolean 0xFF00 = ON, 0x0000 = OFF. Physical effect
0x06Write Single RegisterOne value Setpoint manipulation
0x0F/0x10Write Multiple RangesBulk change — fastest way to do damage

The signature to learn: read → write → re-read. An attacker verifies the change took effect. That read-write-verify pattern is how you tell process manipulation from process monitoring.

Tooling

Passive → active
  • Wireshark / tshark — native dissectors for modbus, s7comm, dnp3, bacnet, cip, goose. Your primary tool.
  • Zeek + ICS parsers — continuous passive asset inventory and logging.
  • Nmap NSE — modbus-discover, s7-info, enip-info, bacnet-info. Active — lab only.
  • plcscan — classic PLC enumeration script (102/502).
  • pymodbus / python-snap7 / pycomm3 — scripting Modbus, S7 and Rockwell respectively.
  • ICSSPLOIT — Metasploit-style framework of ICS modules.
  • Conpot — ICS honeypot; also a safe target to practise against.
  • Shodan / Censys — passive discovery of exposed devices (port:502). Observe only.

Labs you can build

Nothing physical needed
  • GRFICS — a full simulated chemical plant with a 3D process view, HMI and real Modbus. The best free ICS lab there is; you can watch your writes cause a visible process upset.
  • Conpot — stand up a fake Siemens S7 and point tools at it.
  • pymodbus server — ten lines of Python gives you a Modbus slave with real coils and registers to read and write.
  • OpenPLC — a genuine soft-PLC that runs ladder logic and speaks Modbus, pairs well with a simulated process.
  • Factory I/O — commercial process simulator with a free trial; drives from OpenPLC.
  • This site's OT / ICS track — four challenges on real captures: reading a Modbus poll loop, an unauthenticated coil write that opens a breaker, Telnet credentials off a PLC, and an SRP judgement call.

Mapping to ATT&CK for ICS

  • Initial Access — internet-exposed device, engineering workstation via IT, compromised vendor remote access, removable media.
  • Discovery — network sniffing, remote system discovery, device identification requests (0x2B, List Identity, I-Am).
  • Lateral Movement — valid accounts on the jump host, program download to a controller.
  • Collection — point & tag enumeration, monitoring process state, grabbing historian data.
  • Inhibit Response Function — disabling alarms, blocking reporting, defeating the SIS (the TRISIS objective).
  • Impair Process Control — unauthorised command message, setpoint modification, spoofed reporting so the operator sees normal values.
  • Impact — loss of control, loss of safety, damage to property, loss of production.
