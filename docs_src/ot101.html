OT 101: From IT/Cyber to OT

Cyber Club Quick Reference · v1.0

Everything you know about security still applies in Operational Technology — but the priorities invert. IT protects information. OT protects a physical process: pumps, breakers, valves, reactors. When IT fails you lose data; when OT fails you lose containment, or someone gets hurt. That single difference drives every unfamiliar rule you are about to meet, including the ones that look like negligence until you understand them.

The one-line translation: IT ranks Confidentiality first. OT ranks Safety first. Memorize the swap — CIA becomes SRP — and most OT decisions stop being surprising.

CIA — the IT triad

What you know
  • Confidentiality — keep data from those who shouldn't see it. The breach headline. Usually ranked first.
  • Integrity — data is accurate and unaltered.
  • Availability — systems are up when needed. Often the sacrifice: patch now, reboot now, take the outage.

Worst case: data is stolen, leaked or ransomed. Recovery is restore-from-backup and notify.

SRP — the OT triad

What governs plant
  • Safety — nobody is injured, nothing is released. Outranks everything, always. Not negotiable by an individual.
  • Reliability — the process runs correctly and predictably. Bad data driving a real actuator is a physical event.
  • Performance — throughput, quota, efficiency. Last. The thing you give up, not the thing you protect.

Worst case: injury, fire, environmental release, grid instability. There is no restore-from-backup for that.

The Purdue Model

Zones & conduits
  • L4/5 Enterprise — IT, email, ERP. Internet-facing.
  • L3.5 DMZ — the conduit. Historian replica, jump host, patch relay. All IT↔OT traffic terminates here.
  • L3 Operations — historians, engineering workstations.
  • L2 Supervisory — HMIs, SCADA servers.
  • L1 Control — PLCs, RTUs, DCS controllers.
  • L0 Process — sensors and actuators. Physics lives here.

Ask of any flow: which zones does it cross, and does it stop in the DMZ? A path from L4 to L1 is the finding.

Safety Instrumented Systems

Keep separate

An SIS exists to force the process into a safe state when the control system fails or is wrong. It is deliberately separate hardware on a separate network from the DCS/PLC layer.

  • Compromising the control network must not defeat the layer whose only job is preventing harm.
  • Interlocks are safety functions, not obstacles. Bypassing one to hit quota trades Safety for Performance — an inversion of SRP.
  • Bypasses require two-person authorization because the consequence is physical.
  • TRISIS/TRITON (2017) targeted an SIS directly — the first malware built to disable a safety system.

The pattern: these protocols aren't misconfigured — they have no concept of a credential. You cannot patch that. Security has to come from the network around them, which is why segmentation does the heavy lifting in every OT architecture.

First questions on any OT review

Start here
  1. What can reach port 502 (or 102, or 44818) — and from which zone? Reachability is the vulnerability.
  2. Is there a real L3.5 DMZ, or a firewall rule with any→any in it?
  3. Is the SIS physically and logically separate from the control network?
  4. Is there remote vendor access? Always-on VPN, or brokered and time-boxed?
  5. Who is monitoring, and does anyone alert on a first-seen write command?
  6. Does the change-control process include an SRP impact review?

Vocabulary

Decoder ring
  • PLC — programmable logic controller; runs the control loop.
  • RTU — remote terminal unit; a PLC at a remote site.
  • HMI — the operator's screen.
  • DCS — distributed control system; plant-wide, process industries.
  • SCADA — supervisory control and data acquisition; wide-area oversight.
  • Historian — time-series database of process values.
  • Coil / register — a boolean output / a numeric value in a PLC.
  • Setpoint — the target value the loop drives toward.
  • Interlock — logic making an unsafe state unreachable.
  • Air gap — claimed far more often than it exists. Verify.

Incidents worth knowing

  • Stuxnet (2010) — damaged centrifuges by altering S7 logic while showing operators normal values. Proved software can break hardware.
  • Ukraine grid (2015, 2016) — attackers operated breakers through legitimate control protocols. No exploit needed, only reachability.
  • TRISIS / TRITON (2017) — first malware aimed at a safety system; a failed payload triggered the plant trip that exposed it.
  • Colonial Pipeline (2021) — IT ransomware, yet operations stopped. OT impact does not require OT compromise.
  • Oldsmar water (2021) — shared remote-access creds; an operator watched the setpoint for a chemical move on screen.
