Getting Started with Wireshark

Cyber Club Quick Reference · v1.0

Wireshark shows you exactly what crossed the wire — no vendor summary, no log abstraction, just bytes with a timestamp. It is the ground truth tool: when a log and a capture disagree, the capture wins. This guide gets you from first launch to answering real questions: who logged in, what left the network, and what that unexpected host was doing.

The single most useful habit: stop reading individual packets. Right-click → Follow → TCP Stream and read the conversation. Most beginners stall because they grep packets for a string that was split across three of them.

Capture filters

Before — BPF syntax

Applied while capturing. Packets that don't match are discarded forever. Use only when you must limit volume.

  • host 192.168.20.31
  • port 502  ·  tcp port 80 or port 443
  • net 192.168.20.0/24
  • not arp and not broadcast

Display filters

After — Wireshark syntax

Applied to an existing capture. Hides packets without deleting them. This is the one you'll use 95% of the time.

  • ip.addr == 192.168.20.31
  • tcp.port == 502  ·  http || dns
  • http.request.method == "POST"
  • frame contains "password"

The classic mistake: typing port 80 into the display filter bar (invalid — it turns red) or tcp.port == 80 into the capture filter box (also invalid). Two different syntaxes. Capture filters use spaces; display filters use ==.

Statistics menu

Where to start a capture
  • Protocol Hierarchy — what's in here, by percentage. Always open this first. An unexpected protocol at 0.2% is often the whole story.
  • Conversations — every pair of hosts, sorted by bytes. Finds the top talker and the one host that shouldn't be talking at all.
  • Endpoints — every address seen; the Map tab plots external IPs.
  • I/O Graph — traffic over time. Beaconing shows up as a regular comb.
  • Capture File Properties — duration, packet count, drops.

File > Export Objects

Pull files out

Reassembles and saves files that were transferred in the clear — from HTTP, SMB, FTP-DATA, TFTP or IMF (email).

  • Recover a malware sample pulled down over HTTP.
  • Recover documents exfiltrated over SMB.
  • Hash before you open. Treat anything recovered as live malware.

Three real workflows

Do these
  1. Find credentials. Filter http.request.method=="POST" → Follow HTTP Stream → read the body. Repeat for ftp and telnet.
  2. Spot exfiltration. Statistics → Conversations, sort by bytes. Then check DNS: dns.flags.response==0 and look for long random subdomains repeating to one domain.
  3. Confirm a scan. One source, many destination ports, SYNs with no data. Find what answered with tcp.flags.syn==1 && tcp.flags.ack==1, then follow that stream for the service banner.

Capture hygiene & ethics

Read this
  • Get authorization in writing. Capturing traffic on a network you don't own is illegal in most jurisdictions — it is wiretapping.
  • Captures contain credentials and personal data. Treat a .pcap as sensitive evidence: encrypt it, don't paste it in chat.
  • You only see traffic that reaches your NIC. On a switched network use a SPAN port or TAP — not an attack.
  • In OT, never capture actively. Passive TAP only.
  • TLS is opaque without keys. You still get IPs, SNI, sizes and timing.
